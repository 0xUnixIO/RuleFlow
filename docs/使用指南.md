# 使用指南

## 使用流程

1. **添加订阅源** — 在控制台「订阅源」页面填入订阅 URL
2. **同步节点** — 点击同步按钮拉取节点列表
3. **配置规则源**（可选）— 添加规则集订阅源
4. **选择或上传模板** — 使用内置模板或上传自定义模板
5. **创建配置策略** — 绑定订阅源 + 模板 + 目标客户端，生成专属订阅链接
6. **填入客户端** — 将 `/subscribe?token=xxx` 链接填入客户端

## 规则模板

内置模板可直接在线查看或下载使用：

| 客户端 | 文件 |
|--------|------|
| Clash Meta / Stash | [template/clash.yaml](../template/clash.yaml) |
| Surge | [template/surge.conf](../template/surge.conf) |
| Sing-Box | [template/sing-box.json](../template/sing-box.json) |

### 模板占位符

| 占位符 | 适用 | 说明 |
|--------|------|------|
| `__NODES__` | 全部 | 展开为所有代理节点名称列表 |
| `__OUTBOUNDS__` | Sing-Box | 展开为完整出站对象数组 |
| `__ENDPOINTS__` | Sing-Box | 展开为 WireGuard endpoint 数组 |

### 节点过滤字段（Clash / Stash）

在 `proxy-groups` 中支持以下扩展字段，生成时自动处理后从输出中删除：

**`filter`** — 正则，仅名称匹配的节点进入该组

```yaml
proxy-groups:
  - name: 🇸🇬 新加坡
    type: url-test
    filter: "SG|新加坡|Singapore"
    proxies: ["__NODES__"]
    url: http://cp.cloudflare.com/generate_204
    interval: 300
```

**`exclude-filter`** — 在 `filter` 结果中再排除

```yaml
  - name: 🇸🇬 新加坡（精品）
    type: url-test
    filter: "SG|新加坡"
    exclude-filter: "IPLC|BGP|中转"
    proxies: ["__NODES__"]
```

**`dialer-proxy`** — 链式代理，正则匹配中转节点（组名优先，找不到时按节点名匹配）

```yaml
  - name: 🇺🇸 美国 via 新加坡
    type: select
    filter: "US|美国"
    dialer-proxy: "SG|新加坡"
    proxies: ["__NODES__"]
```

生成时 `dialer-proxy` 会被翻译为每个落地节点行的 `underlying-proxy=` 参数，原字段不保留在输出中。

### 节点过滤字段（Surge）

```ini
[Proxy Group]
🇸🇬 SG = url-test, __NODES__, policy-regex-filter=SG|新加坡, interval=300
🤖 AI = select, __NODES__, policy-regex-filter=US|美国, exclude-filter=IPLC|BGP, dialer-proxy=🇸🇬 SG
```

`policy-regex-filter=`、`exclude-filter=`、`dialer-proxy=` 生成后均不保留；`dialer-proxy` 同样翻译为节点行的 `underlying-proxy=` 参数。

### 节点过滤字段（Sing-Box）

在 `selector` / `urltest` 出站中使用 `filter` 字段（正则），`detour-proxy` 实现链式代理：

```json
{
  "type": "urltest",
  "tag": "🇯🇵 JP",
  "outbounds": ["__NODES__"],
  "filter": "🇯🇵|日本|JP"
},
{
  "type": "selector",
  "tag": "🤖 AI",
  "outbounds": ["__NODES__"],
  "filter": "US|美国",
  "detour-proxy": "🇯🇵 JP"
}
```

`detour-proxy` 生成时翻译为每个节点的 `detour` 字段，原字段不保留。

## 规则源与 RULE-SET 用法（Surge）

Surge 模板中的 `RULE-SET` 支持两种来源：

### 1. RuleFlow 内置规则源

路径以 `/rulesets/` 开头即为本地规则源，由控制台「规则源」页面管理：

```ini
[Rule]
RULE-SET,/rulesets/ai-proxy?target=surge,🤖 AI
RULE-SET,/rulesets/need-direct?target=surge,DIRECT
```

- `/rulesets/{名称}` 中的名称对应规则源的名称
- `target=surge` 表示以 Surge 经典格式输出
- 规则源内容在控制台管理，更新后订阅自动生效

### 2. 外部远程规则集

直接填写公网 URL，Surge 客户端自行拉取：

```ini
[Rule]
RULE-SET,https://ruleset.skk.moe/List/non_ip/reject-drop.conf,REJECT-DROP,pre-matching
RULE-SET,https://ruleset.skk.moe/List/non_ip/ai.conf,🤖 AI
```

- 末尾可加 `pre-matching`，Surge 会在路由判断前优先匹配该规则集（适合拦截类规则）
- 外部 URL 由 Surge 客户端直接请求，不经过 RuleFlow

## 卸载

```bash
curl -fsSL https://raw.githubusercontent.com/0xUnixIO/RuleFlow/main/uninstall.sh | sh
```

若 Docker 不可用，脚本会跳过容器清理，直接删除安装目录（默认 `~/ruleflow`）。

如安装在自定义路径，请指定目录：

```bash
RULEFLOW_DIR=/your/path curl -fsSL https://raw.githubusercontent.com/0xUnixIO/RuleFlow/main/uninstall.sh | sh
```
